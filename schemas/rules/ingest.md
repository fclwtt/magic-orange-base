# Schema Ingest — 参考手册回补规则

> 本规则教 Agent 如何将查阅过程中的新发现回补到参考手册中，形成知识复利。

## 回补原则

1. **及时回补** — 发现新信息立即回补，不要等到最后
2. **注明来源** — 回补的内容要标注来源（哪次查阅、哪个任务）
3. **保持索引** — 回补的内容必须包含路径索引，方便后续定位
4. **不重复** — 回补前检查手册中是否已有该信息

## 回补触发条件

以下情况必须回补：

1. **发现新模块** — 查阅时发现手册中未记录的模块
2. **发现新接口** — 发现手册中未记录的重要接口
3. **发现设计决策** — 从代码注释、README、PR 中发现设计决策
4. **发现坑点** — 遇到已知问题、workaround、注意事项
5. **发现关联** — 发现模块间的新依赖关系

## 回补流程

### 1. 定位回补位置

根据新发现的类型，定位到手册的对应章节：
- 新模块 → "关键模块索引" 表格
- 新接口 → "接口设计" 章节
- 设计决策 → "设计哲学" 章节
- 坑点 → "配置与约定" → "已知坑点"
- 关联关系 → "架构设计" → "模块间依赖"

### 2. 格式化回补内容

每条回补内容必须包含：
- **内容**：简明扼要的描述
- **索引**：文件路径或代码位置
- **来源**：哪次查阅发现的（日期 + 任务）

格式示例：
```markdown
| 模块 | 路径 | 说明 | 来源 |
|------|------|------|------|
| Agent Harness | packages/agent-core/harness/ | 编排层，包装 Inner Loop | 2026-07-01 Loop Engineering 改造 |
```

### 3. 更新查阅日志

在手册末尾的"查阅日志"部分添加：
```
- YYYY-MM-DD: 回补了 XX 信息（来源：YY 任务）
```

### 4. 更新"最后更新"时间

更新手册头部的"最后更新"字段。

## 回补示例

### 示例 1：发现新模块

查阅 OpenClaw 时发现了一个手册中未记录的模块 `agent-harness.ts`：

```markdown
## 关键模块索引

| 模块 | 路径 | 说明 | 来源 |
|------|------|------|------|
| ... | ... | ... | ... |
| Agent Harness | packages/agent-core/harness/agent-harness.ts | 编排层，管理 Agent 生命周期，调用 Inner Loop | 2026-07-01 Loop Engineering 改造 |
```

**注意**：回补后，如果发现了重要的新知识，可以考虑更新 `schemas/index.md` 中该手册的概要。

### 示例 2：发现设计决策

从代码注释中发现了一个重要的设计决策：

```markdown
## 设计哲学

### 状态外置
- 循环本身不持久化任何状态，所有持久化由上层 Harness 完成
- 来源：2026-07-01 查阅 agent-loop.ts 注释
- 索引：packages/agent-core/agent-loop.ts:42-45
```

### 示例 3：发现坑点

```markdown
## 配置与约定

### 已知坑点
- Inner Loop（runAgentLoop）不可修改，所有扩展必须在外层
  - 来源：2026-07-01 Loop Engineering 改造
  - 索引：packages/agent-core/agent-loop.ts
```

## 回补禁忌

- ❌ 不要回补没有路径索引的信息
- ❌ 不要回补重复的信息（先检查手册）
- ❌ 不要回补临时性的、无长期价值的信息
- ✅ 回补有索引、有来源、有长期价值的信息

## 知识复利

每次回补都是对知识库的投资：
- 下次查阅时，可以直接从手册获取信息
- 不需要重新探索整个代码库
- 知识越积越多，查阅效率越来越高

这就是"知识复利"——今天的回补，节省明天的探索时间。
