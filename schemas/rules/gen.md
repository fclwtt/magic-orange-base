# 参考手册生成规则

## 核心原则

1. **一次生成，多次查阅** — 参考手册是项目的"压缩知识"，避免每次重新探索
2. **索引优先** — 不复制代码，只记录"什么在哪里"，用路径索引定位
3. **多维度** — 覆盖架构、接口、设计哲学、目录结构、关键模块等
4. **可增量更新** — 发现新信息时可以回补到手册中
5. **格式统一** — 所有参考手册遵循相同的结构和维度

## 调查方法（必须遵循）

### 第一步：项目概览探索

使用 `find` / `ls` 探索项目根目录，识别：
- 项目名称（从 package.json、README.md、pyproject.toml 等）
- 技术栈（从配置文件推断）
- 项目类型（单体、monorepo、库、应用等）

### 第二步：按维度深入调查

**必须按以下 7 个维度逐一调查**，每个维度都有明确的调查方法：

#### 维度 1：项目概述
- **调查方法**：读取 README.md、package.json、pyproject.toml 等元数据文件
- **提取内容**：
  - 项目名称、版本、许可证
  - 定位和核心功能（一句话描述）
  - 技术栈（语言、框架、构建工具）
  - 与其他项目的关系（依赖、被依赖）

#### 维度 2：目录结构
- **调查方法**：`ls` 根目录，然后对关键子目录递归探索
- **提取内容**：
  - 顶层目录树（2-3 层）
  - 每个目录的职责（从命名和文件内容推断）
  - 文件命名约定（kebab-case、camelCase 等）
  - 特殊目录的用途（src/、core/、packages/、lib/ 等）

#### 维度 3：架构设计
- **调查方法**：
  1. 读取入口文件（index.ts、main.ts、app.ts 等）
  2. 追踪调用链，理解模块间关系
  3. 读取架构文档（ARCHITECTURE.md、docs/ 等）
- **提取内容**：
  - 整体架构模式（分层、微服务、插件化、事件驱动等）
  - 核心模块及其职责
  - 模块间依赖关系（谁调用谁）
  - 数据流向（输入 → 处理 → 输出）
  - 架构图（如果文档中有）

#### 维度 4：接口设计
- **调查方法**：
  1. 搜索 `export`、`interface`、`type`、`class`、`def` 等关键字
  2. 读取核心模块的公开 API
  3. 查看测试文件了解使用方式
- **提取内容**：
  - 核心 API/接口定义（函数签名、类方法）
  - 接口命名约定（动词+名词、名词+动词等）
  - 参数/返回值模式（选项对象、位置参数等）
  - 错误处理模式（异常、错误码、Result 类型等）
  - 扩展点（Hook、Plugin、Middleware 等）

#### 维度 5：设计哲学
- **调查方法**：
  1. 读取 README、CONTRIBUTING.md、AGENTS.md 等文档
  2. 分析代码注释中的设计决策
  3. 从代码风格推断原则
- **提取内容**：
  - 核心设计原则（从文档和代码推断）
  - 权衡取舍（为什么选择 A 而不是 B）
  - 反模式（项目明确避免的做法）
  - 项目口号或愿景（如果有）

#### 维度 6：关键模块索引
- **调查方法**：
  1. 列出所有核心模块（从架构设计中提取）
  2. 对每个模块，找到其文件路径
  3. 用一句话说明其职责
- **提取内容**：
  - 表格格式：模块名 | 路径 | 说明
  - 按功能分组（核心、工具、配置、测试等）

#### 维度 7：配置与约定
- **调查方法**：
  1. 读取 package.json scripts、Makefile、pyproject.toml 等
  2. 读取 .eslintrc、tsconfig.json、.prettierrc 等配置
  3. 搜索 "TODO"、"FIXME"、"HACK" 等注释
- **提取内容**：
  - 构建命令（install、build、dev 等）
  - 测试命令（test、test:watch 等）
  - 代码规范（lint、format 等）
  - 已知坑点（从注释和文档提取）

### 第四步：保存位置

参考手册保存到 `<当前项目根目录>/schemas/references/<project-name>.md`

例如：`https://github.com/openclaw/openclaw`

### 第五步：更新索引

生成参考手册后，必须更新 `schemas/index.md`，添加新手册的条目。
