  • • leverage：一个接口，N 个调用点
  • • 测试从集成变为单元
  • • 删除 3 个浅层包装器

Wins

  • • 删除 35+ 浅层类型文件

3. 压平插件三层适配器

Worth exploring adapter
src/plugins/types.ts · hook-runtime.ts · src/agents/agent-tools.ts · packages/plugin-sdk/

Before — 三层适配

flowchart TD
    REG["registerPlugin"] --> API["OpenClawPluginApi 70+方法"]
    API --> PA["PluginApi"]
    PA --> RPA["RuntimePluginApi"]
    RPA --> AT["agent-tools 动态注册"]
    style API fill:#dc2626,stroke:#991b1b,color:#fff
    style PA fill:#f59e0b,stroke:#d97706,color:#fff
    style RPA fill:#f59e0b,stroke:#d97706,color:#fff

After — 两层适配

flowchart TD
    REG2["registerPlugin"] --> API2["PluginApi ~30方法"]
    API2 --> EX2["执行"]
    style API2 fill:#0f172a,stroke:#0f172a,color:#fff

合并 PluginApi + RuntimePluginApi，删除冗余层

Problem

插件注册经过三层适配器，两层 adapter 只是转发调用，无额外隔离价值。agent-tools.ts 运行时动态注入工具增加隐式耦合。

Solution

合并 PluginApi 和 RuntimePluginApi 为一层。工具注册改为声明式配置，而非运行时动态注入。

Wins

  • • leverage：一层适配 = 真正的接缝
  • • 工具注册可静态分析
  • • 测试插件只需 mock 一层

4. 分解 Gateway 命名空间

Worth exploring in-process
src/gateway/ (749 文件) · local-request-context.ts · session-manager.ts

Before — 单体命名空间

gateway/ — 749 文件

HTTP 路由 · WebSocket · 会话管理 · 请求上下文 · 消息投递 · 认证 · 限流

"Don't touch" zone — 任何修改都有副作用

After — 聚焦子模块

http-router/
ws-transport/
session-lifecycle/
request-scope/
delivery-pipeline/

Problem

gateway/ 是项目最大命名空间（749 文件），HTTP、WebSocket、会话、投递等职责混杂。session-manager.ts 有 20+ 内部依赖。

Solution

按职责拆分为 5 个子模块，每个有独立接口和测试。通过 request-scope 统一连接。

Wins

  • • locality：修改 WebSocket 不影响 HTTP
  • • 每个子模块可独立测试
  • • 新贡献者聚焦单一子模块

Problem

工具处理器直接导入 fs、child_process、http，产生隐式副作用。测试需 mock 整个系统调用链。沙箱策略与工具逻辑耦合。

Solution

引入端口接口（FileSystemPort、ProcessPort、NetworkPort），工具依赖端口而非实现。生产注入真实适配器，测试注入 mock。

Wins

  • • 测试工具只需 mock 端口接口
  • • 沙箱策略与工具逻辑解耦
  • • 两个适配器 = 真正的接缝

Problem

  • • 每个子模块可独立测试
